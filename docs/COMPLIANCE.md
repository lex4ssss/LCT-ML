# Соответствие ТЗ: ML-часть

Где в решении закрыто каждое требование ТЗ задачи 8, относящееся к прогнозированию. Цифры взяты из отчётов в outputs/, рядом с каждой стоит базовая доля и правило. Требования к интерфейсу, ролям, аудиту и заявкам закрывает backend, их строки внизу.

## Прогнозирование

| Требование ТЗ | Где в решении | Подтверждение |
|---|---|---|
| Вероятность инцидента с горизонтом не менее 24 ч | Модель объекта run-008: инцидент на горизонте 72 ч. `POST /risk_map` и `POST /predict_object` отдают вероятность после isotonic-калибровки на 2025 году | ml-baseline-v2/README.md, раздел «Explore-v8 и run-008» |
| Прогноз отказа датчика или оборудования | Модель run-009: состояние «Неисправен» на горизонте 168 ч, тот же сервис с `target=failure` | ml-baseline-v2/README.md, раздел о run-009 |
| Локация оборудования под риском | Ответ привязан к объекту справочника; `suspect_channels` называет до трёх самых подозрительных каналов внутри объекта с типом датчика | ml-service/README.md, «Прогноз по объекту» |
| Классификация типа инцидента | Отказ и инцидент прогнозируются раздельно (§16 ответов организаторов). Тип инцидента backend берёт из типа первого подозрительного датчика | object_risk_sync.py в backend |
| Объяснение прогноза | `top_factors`: три главных признака объекта по SHAP с читаемыми значениями | ml-service/README.md |
| Сценарный анализ: пожар, проникновение, подтопление | explore-v7 проверил 7 целей, среди них дверь или люк, подтопление и дым. Отбор на 2025 году прошли инцидент в целом и дверь или люк; остальные цели отклонены с цифрами | ml-baseline-v2/README.md, «Explore-v7 и run-007» |
| Рекомендации по обслуживанию на основе состояния оборудования | Прогноз отказа насосов на синтетических данных организаторов: 30 мин и 1 ч проходят 0,7 / 0,5 на test | ml-pumps/README.md |
| Метеоданные как внешний источник | Проверены городская погода и Open-Meteo с осадками (run-003, run-004). Качество не выросло, поэтому погода в модель не включена | ml-baseline-v2/README.md, «Run-003», «Run-004» |

## Метрики качества

| Требование ТЗ | Где в решении | Подтверждение |
|---|---|---|
| Precision и Recall определяются и измеряются | Ориентир организаторов 0,7 / 0,5. Инцидент 72 ч, test 2026: 0,827 / 0,616 при базовой доле 0,347; правило «тревога в объекте за сутки» 0,573 / 0,492. Отказ 168 ч, test 2026: 0,869 / 0,625 | ml-baseline-v2/README.md, validate-objects.json |
| Честность оценки | Правило отбора закоммичено до прогона, отбор только на 2025 году, test 2026 открывается один раз для победителя с порогом с 2025 года. Все предыдущие взгляды на test перечислены | docs/VERIFICATION.md |
| Устойчивость во времени | Помесячная проверка на test 2026 и bootstrap-интервалы для обеих моделей | ml-baseline-v2/validate_stability.py, validate-stability.json |
| Отслеживание качества по фидбэку диспетчера | Решения и причины отклонения хранит backend; модель можно переоценить на них тем же скриптом проверки | backend: reject с reason_code |
