# Прогноз отказа насоса на синтетическом датасете

Данные полностью синтетические. Их сгенерировал скрипт new-gen.py из архива «МРОН datasets.zip» для четырёх насосов NPV_2_1…NPV_2_4. Все цифры ниже относятся к синтетике и о реальных насосах ничего не говорят.

## Результат run-001

Модель предупреждает об отказе насоса за 30 минут и за 1 час. Оба горизонта прошли критерий P ≥ 0,7 при R ≥ 0,5. Проверка шла на validation, затем test открыли один раз с порогом, выбранным на validation.

| горизонт | test P / R | F1 | доля событий | правило P / R | F1 правила |
|---|---|---|---|---|---|
| 30 мин | 0,727 / 0,513 | 0,601 | 0,047 | 0,072 / 0,351 | 0,120 |
| 1 ч | 0,778 / 0,559 | 0,651 | 0,091 | 0,133 / 0,332 | 0,190 |

Правило срабатывает по порогам из описания датасета: вибрация выше 2,8 мм/с, ток выше 82 А, перепад на фильтре выше 0,15 МПа или температура выше 80 °C.

Полнота на test зависит от типа отказа. Для горизонта 1 ч: несоосность 0,69, засорение фильтра 0,51, неизвестная неисправность 0,05. Неизвестную неисправность модель почти не видит заранее.

Горизонты 8 ч и 24 ч критерий не проходят по доле событий: 0,52 и 0,9996 при допустимых 0,35. В этих файлах каждая траектория кончается отказом не позже чем через сутки, поэтому почти любая строка оказывается положительной.

Источник чисел: run-001/report.json.

## Как устроены данные

1. Малый файл `(1).csv` (10 000 строк) не подходит. В нём насос и отказ выбираются случайно для каждой строки, а `time_to_next_fault_hours` не связан со следующим отказом: корреляция −0,02.
2. В основном файле (1 236 656 строк) лежат 9 500 траекторий длиной 1, 8 или 24 часа с шагом 5 минут. Метка отказа стоит на последней строке. Все траектории начинаются в 2025-07-14 00:00, поэтому их пришлось собирать заново по порядку строк внутри одного момента времени. Сборку проверяют: длина, одна метка в конце, число строк на каждом шаге.
3. Два файла для повторной проверки собрать не удалось. В каждом одна нормальная строка попала внутрь окна траекторий (шаги 1 и 2), и сборка останавливается на проверке числа строк. Поправка сборки под этот случай потребует новой spec.

## Протокол

Spec spec_pumps_v1.txt закоммичен до первого прогона. Признаки берутся из текущей строки и предыдущих строк той же траектории: 12 датчиков, тип насоса, изменение каждого датчика за 12 шагов и средний шаг изменения. Время, номер шага, `anomaly_score_*`, `status` и поля типа отказа в признаки не входят: генератор считает оценки аномалии прямо из тяжести дефекта.

Выборки делятся по порядку генерации, отдельно по каждому насосу: 60 % траекторий на обучение, 20 % на validation, 20 % на test. Модель HistGradientBoosting, отдельная для каждого горизонта, параметры по умолчанию.
