# Первый ML-baseline

Логистическая регрессия обучена и проверена на validation. Она улучшает F1 относительно простого правила, но текущего качества недостаточно для рабочего прогноза. Шаг 3 остаётся открытым: test не оценивался, калибровка не обучалась, сервис не подключён.

## Постановка и режим

Цель: новый записанный тревожный эпизод канала в следующие сутки. Единица построчной оценки: канал в полночь UTC, имеющий пригодную историю предыдущих суток. Это не прогноз подтверждённого физического отказа.

Режим эксперимента run-001: очистка и маски пропусков включены; признаки и горизонт по 24 часа; эпизоды объединяются при паузе до 900 секунд; общие паузы журнала выявляются от 3600 секунд. Обучение только на train, подбор порога и оценка на validation включены. Подбор гиперпараметров, веса классов, дополнительная калибровка, оценка test и онлайн-инференс выключены. Предположение о часовом поясе источника: Europe/Moscow.

Train содержит 3 351 044 пригодных снимка и заканчивается до 2025 года с исключением пересекающихся будущих окон. Validation содержит 570 662 снимка 2025 года, из них 12 819 положительных. Test 2026 года зарезервирован. Все сравниваемые методы используют одинаковые строки validation и одну метку.

## Модель и сравнение

Признаки: число записей, число тревог, давность последней записи и давность последней тревоги за прошлые сутки. Отсутствующая тревога получает давность 24 часа. Далее применяется log1p, стандартизация по train и LogisticRegression с C=1, solver=lbfgs, max_iter=500, tol=1e-6, без весов классов. Обучение сошлось за 16 итераций, предупреждения о несходимости не было.

Порог 0,07780670014406951 выбран по максимальному F1 на validation; при равенстве выбирается больший порог. Поэтому F1 этого же периода оптимистичен относительно независимой проверки. Порог не является оценкой вероятности аварии.

| Метод | Precision | Recall | F1 | Average precision |
|---|---:|---:|---:|---:|
| Логистическая регрессия | 21,38% | 38,43% | 27,47% | 18,79% |
| Тревога в прошлые сутки | 16,21% | 49,46% | 24,42% | 9,15% |
| Постоянный score по частоте train | 0% | 0% | 0% | 2,25% |

Для правила положительный прогноз означает хотя бы одну тревогу в прошлом окне. Постоянный score равен 0,0206974304 и при пороге 0,5 не создаёт предупреждений; нулевой F1 этого метода ожидаем. Average precision постоянного ранжирования равна доле положительных меток validation. Это сравнение качества ранжирования, не доказательство пригодности выдавать числовую вероятность.

Brier на том же validation равен 0,020435 для логистической регрессии и 0,021962 для константы. Близость общей ошибки к константе при редком событии сама по себе не доказывает хорошую калибровку. Для бинарного правила Brier в selection.json относится к жёстким значениям 0/1 и не трактуется как качество обученной вероятности.

## Что проверено

1. Все преобразования обучаются только на train. В отдельном тесте 20 раз изменялись строки test, включая значения, недопустимые для обучения. Коэффициенты, порог и отчёт оставались одинаковыми. Все тесты прошли; test в этих проверках синтетический.
2. Загруженный model.joblib прошёл 20 проверок на воспроизводимых искусственных данных: изменение размера пакета не меняло прогноз, выход оставался конечным в диапазоне от нуля до единицы. Обучение и оценка реального test в этих проверках выключены.
3. Существующий каталог результата не перезаписывается. Модель сохраняет весь pipeline, чтобы при инференсе применялись те же заполнение пропусков, логарифмирование и стандартизация.

Детальное ревью и ограничения находятся в REVIEW.md.

## Повторение

Команды запускаются из корня рабочей папки. Для обучения нужен новый каталог результата. Зависимости текущего окружения зафиксированы в requirements.txt.

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 PYTHONDONTWRITEBYTECODE=1 \
  work/data-env/bin/python outputs/ml-baseline/fit_baseline.py \
  work/ml-prepared/training-examples.parquet outputs/ml-baseline/run-reproduced

OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 PYTHONDONTWRITEBYTECODE=1 \
  work/data-env/bin/python -m unittest discover \
  -s outputs/ml-baseline -p 'test_*.py'
```

Перед следующим обучением следует зафиксировать признаки с более длинной историей и критерий выбора модели. Test остаётся закрытым для подбора решений. Новый эксперимент должен отдельно показывать покрытие эпизодов, число ложных предупреждений и качество по времени, а не только общий F1.
