run-005: HGB v2 plus object and channel-type features, folds A and B only, no test evaluation.

Written on 2026-09-26 before run-005 results were seen.

Input: training-examples-v2.parquet (sha must equal run-002 input_sha256), object-features-v3.parquet built by ml-dataset-v2/object_features.py
from the same examples and справочник_каналов_датчиков.csv.
Baseline: run-002/report.json candidates.hgb, same examples, folds and HGB parameters, random_state=0.

Added features per (channel, as_of), all from the past only because they sum past-only v2 features of the other channels of the same object at the same as_of:
obj_channels_30d, obj_other_alarm_channels_24h, obj_other_alarm_24h, obj_other_alarm_7d, obj_other_episode_starts_7d, obj_other_episode_starts_30d,
type_other_alarm_7d (same object and sensor type), plus sensor_type and system_type as HGB categorical features.
Channels missing from the directory (4.7% of rows) get NaN object features and NaN categories.
The directory is a static snapshot; sensor and system type are treated as fixed attributes of a channel.

Acceptance rule, the same as run-003 and run-004, fixed before results:
accepted only if hgb_objects beats baseline hgb on both
1. selection_2024 average_precision by at least 0.005 absolute, and
2. retrained.all average_precision on 2025 by at least 0.005 absolute,
and frozen.all F1 on 2025 at the fold A threshold is not lower than baseline by more than 0.005.
Object-day metrics for 2025 are reported for information and do not enter the decision.

If accepted: decide a new threshold on 2025 as in final_v2, one evaluation on test 2026 marked as a second look at the same test, and the service gains the object features.
