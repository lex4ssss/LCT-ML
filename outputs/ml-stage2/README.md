# Сборка тревожных эпизодов

Сборка расчётных групп тревог по каналу реализована и проверена. Это компонент второй части ML-задачи. Модуль не устанавливает факт поломки, восстановления или простоя датчика. Признаки, обучающие метки и временные выборки пока не реализованы.

## Правило

1. Нормализовать журнал загрузчиком из соседней папки ml-stage1. Часовой пояс передаётся явно.
2. Отсортировать все записи по каналу и времени UTC через временную SQLite-базу. Строки с одинаковой отметкой сохраняют входной порядок.
3. Объединить соседние тревожные строки одного канала, если разрыв между ними не превышает gap_seconds. Равенство входит в эпизод. Длинная цепочка может длиться больше gap_seconds.
4. Сохранить начало и конец наблюдаемых тревог, количество строк и определимость границ по этому входу.

Параметр gap_seconds обязателен, рабочего значения по умолчанию нет. Обычные строки не означают подтверждённое восстановление и не разрывают группу сами по себе. Повторы идентификаторов и одинаковые отметки сохраняются: правила удаления повторов полного архива ещё не согласованы.

## Границы

first_alarm_at и last_alarm_at обозначают первую и последнюю тревожную строку группы. Это не фактическое начало и окончание происшествия.

left_boundary и right_boundary принимают unknown или observed_quiet_gap. Второе значение означает только наличие интервала строго больше gap_seconds без тревожных строк в данном входе:

- Для первой группы канала левая граница опирается на первую доступную строку этого канала. Для последующих групп её задаёт разрыв с предыдущей тревогой.
- Правая граница требует более поздней строки того же канала, отстоящей от последней тревоги строго больше gap_seconds. Строка другого канала для этого не подходит.

Пропуски доставки, отключение датчика и полнота журнала не проверены. Даже observed_quiet_gap нельзя использовать как доказательство исправности или готовую отрицательную метку. unknown сохраняет неопределённость на краях файла.

## Запуск

Сохраните папки ml-stage1 и ml-stage2 рядом. Зависимости входят в стандартную библиотеку Python. Команда ниже рассчитана на текущую рабочую папку задачи; для другого журнала замените путь после --events.

```bash
python3 outputs/ml-stage2/build_episodes.py \
  --events 'work/LCT-backend/data/журнал_событий_пример.csv' \
  --source-timezone Europe/Moscow \
  --gap-seconds 900 \
  --output outputs/ml-stage2/episodes-900.jsonl
```

Значение 900 в примере служит проверке механики. Оно не выбрано как оптимальное и не утверждено для обучения. Europe/Moscow соответствует допущению backend; фактический часовой пояс исходной системы отдельно не подтверждён. Файл episodes-900.jsonl уже создан этим запуском; для повторного расчёта задайте другое имя выхода.

CLI печатает JSON с параметрами и счётчиками. Существующий выходной файл не перезаписывается. Ошибка структуры, времени или значения тревожности прерывает весь запуск без публикации частичного файла. Временная база удаляется при обычном завершении и обрабатываемых исключениях; принудительное завершение процесса может оставить временный каталог.

Для обработки нужен запас дискового места под базу, сортировку и результат. Хранение всего входа в Python-списке не используется. Скорость и дисковый объём полного архива не измерялись.

## Проверка

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s outputs/ml-stage2 -p 'test_*.py'
```

Независимая сверка на примере:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 outputs/ml-stage2/verify_sample.py \
  --events 'work/LCT-backend/data/журнал_событий_пример.csv' \
  --source-timezone Europe/Moscow
```

verify_sample.py предназначен для небольшого тестового примера и ограничивает вход 200 000 строками. Основной путь обработки находится в build_episodes.py; ограничение проверочного скрипта к нему не относится.

Новый компонент прошёл 22 тестовых метода на искусственных данных, включая 200 сравнений с независимым расчётом. Обучение, инференс и сеть выключены. Проверки исходного журнала с сортировкой, без удаления повторов и вывода о восстановлении дали полное совпадение с независимым расчётом. Подробности, исправленные дефекты и ограничения сохранены в REVIEW.md, параметры прогонов в sample-validation.json и episodes-900-run.json.

При прямом использовании iter_episodes поздняя ошибка может возникнуть после выдачи ранних групп. Атомарная публикация всего результата обеспечивается CLI, а не генератором.

## Ограничения для обучения

Группы строятся ретроспективно. Поздние тревоги и правые границы нельзя переносить в признаки более раннего момента расчёта: это утечка будущего. Время фактического поступления записей отсутствует, поэтому воспроизводимость исторической доступности ещё не доказана.

Доступный файл охватывает меньше суток. В нём нет полного будущего окна 24 часа для моментов внутри файла. Обучение и оценка качества прогноза здесь не проводятся. Следующая самостоятельная работа: признаки из прошлого и метки с исключением неполных будущих окон; запуск на реальной временной выборке требует архива.
