# Загрузчик и аудит данных Москоллектора

Загрузчик читает журнал событий потоком, нормализует время и идентификаторы, проверяет связи каналов с объектами и выдаёт JSON-отчёт о качестве. Он не обучает модель и не строит разметку поломок.

Проверен на файлах из Runoi/LCT-backend, коммит 928b9931da16ca53498425316482d19bc40f11ba. Используются только библиотеки Python: установка зависимостей не требуется. Проверено установленным в этой среде python3.

## Запуск на имеющемся примере

Команда ниже выводит отчёт в терминал. Она работает из любой папки в текущей среде.

```bash
python3 outputs/ml-stage1/profile_data.py \
  --events work/LCT-backend/data/журнал_событий_пример.csv \
  --channels work/LCT-backend/data/справочник_каналов_датчиков.csv \
  --facilities work/LCT-backend/data/справочник_объектов_диспетчер.csv \
  --source-timezone Europe/Moscow
```

Europe/Moscow задан явно, в соответствии с существующим парсером backend. Часовой пояс исходной системы ещё не подтверждён владельцем данных. Он не выводится из содержимого файла автоматически.

Для сохранения добавьте `--output /абсолютный/путь/к/новому-отчёту.json`. Родительская папка должна существовать. Существующие файлы не перезаписываются, в том числе при случайном указании пути входного CSV.

Коды завершения: `0` означает успешно сформированный отчёт без отвергнутых строк и неизвестных каналов; `2` означает сформированный отчёт с такими проблемами; `1` означает невозможность завершить аудит. Ошибки аргументов командной строки также возвращают `2`, но без JSON-отчёта. Успешный выход не означает пригодности данных для обучения.

## Состав

1. `event_reader.py`: чтение CSV и нормализация отдельного события. `iter_rows` выдаёт записи последовательно; `normalize_event` возвращает ID события, ID канала, время UTC, флаг тревоги и неизменённое исходное значение.
2. `audit.py`: проверка справочников и потоковое накопление агрегатов. Ошибочные значения отдельных событий учитываются отдельно. Неизвестный канал не удаляется из общего числа корректно разобранных записей.
3. `profile_data.py` и `columns.json`: CLI и соответствие исходных заголовков полям загрузчика. Поддерживаются UTF-8 с BOM или без него, запятые и переносы строк внутри кавычек.
4. `test_reader.py`, `test_audit.py`, `test_cli.py`: независимые тесты входных форматов, времени, счётчиков, ошибок и сохранности файлов.
5. `sample-audit.json`, `validation.json`, `streaming-validation.json`, `REVIEW.md`: результат на примере, проверка источников, измерение памяти и подробное ревью.

## Проверка одной командой

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s outputs/ml-stage1 -p 'test_*.py'
```

Пройдены 19 тестовых методов с параметризованными случаями. Тесты используют временные синтетические файлы; обучение, инференс, replay и удаление дублей выключены. См. REVIEW.md для разбора покрытия и ограничений.

## Результат на примере

Режим: чтение потоком и нормализация времени включены; ошибочные строки считаются отдельно; удаление дублей, классификация числовых значений, replay, синтетические данные, обучение и инференс выключены.

Прочитаны 169 993 записи; 207 имеют флаг тревоги. Все 1 241 канала журнала сопоставились с каталогом. В каталоге 11 485 каналов; справочник объектов содержит 95 записей иерархии. Это не число обслуживаемых объектов: по первичному аудиту каналы привязаны к 78 объектам.

Время в исходном журнале: 1 августа 2026 года с 00:00:00 до 23:59:58. После применения явно выбранного Europe/Moscow это 31 июля 21:00:00 — 1 августа 20:59:58 UTC. Календарная смена даты при переводе в UTC ожидаема.

С указанными выше переключателями повторный запуск CLI занял 1,481 секунды; пиковый RSS процесса по resource.getrusage на macOS составил 20 889 600 байт. Это одно локальное измерение, не прогноз производительности полного архива. Поля отчёта сверены с независимым предварительным подсчётом; входные файлы совпадают с Git-объектами указанного коммита.

## Что ещё не сделано

Дубликаты событий не проверяются: `duplicate_event_ids=not_checked`. Сохранение всех ID в RAM для полного архива запрещено выбранной архитектурой; для точной проверки потребуется отдельная дисковая процедура.

Полнота наблюдения не подтверждена: `observation_coverage=not_verified`. Пустой период не превращается в отрицательную метку. Служебные значения датчиков не классифицируются без правил по типам оборудования. Ошибочные строки учитываются по причинам, но их содержимое и номера не выгружаются в отдельный карантинный файл.

Структурно повреждённый CSV, неверная кодировка, отсутствующая колонка или неоднозначный справочник останавливают аудит. Загрузчик не пытается угадать правильный формат. Повреждённый хвост файла не выдаётся за полностью проверенную выгрузку.

Память зависит от числа уникальных каналов и размера справочников, а не только от фиксированного буфера чтения. Проверка на полном историческом архиве ещё не выполнена. Этот пример покрывает менее суток и не позволяет проверить прогноз на будущие 24 часа.
