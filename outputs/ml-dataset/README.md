# Подготовка ML-выборки

Выборка собрана и проверена на полном архиве. История очищена и приведена к UTC, эпизоды, признаки, метки и временные части сохранены. Этот этап не обучает модель; эксперименты находятся отдельно в ml-baseline.

## Подготовленные данные

Режим подготовки: удаление точных повторов и повторного заголовка, нормализация времени включены; пропуск прочих некорректных строк, преобразование значений датчиков в числовой тип, обучение и инференс выключены.

Из 313 546 017 входных строк сохранены 312 982 076. Удалены 563 940 полностью одинаковых повторов исходных полей и один повторный заголовок. После очистки осталось 2 466 978 тревожных строк. Различающиеся записи с одинаковым ID сохранены. Подробности находятся в preparation-summary.json и годовых отчётах *-preparation.json.

Parquet-файлы с подготовленными наблюдениями расположены в work/ml-prepared/2019.parquet–2026.parquet. Поля: event_id, channel_id, occurred_at, is_alarm, raw_value. occurred_at хранит время UTC без встроенного объекта часового пояса. Внешнему API его следует передавать с явным UTC-смещением. Исходный часовой пояс Europe/Moscow принят по backend, а не подтверждён владельцем исходной системы.

Эпизоды находятся в work/ml-prepared/episodes-900.parquet. Режим: подготовленные данные с указанной выше очисткой; интервал объединения 900 секунд; вывод о физическом восстановлении, обучение и инференс выключены. Получено 502 535 групп, охватывающих все тревожные строки. Интервал является кандидатом для первого эксперимента, не оптимизированным параметром. SQL сверена с независимой потоковой реализацией на граничных случаях и 200 воспроизводимых случайных наборах.

## Рабочая постановка

Предсказывается начало нового тревожного эпизода, записанного в журнале, в следующие сутки. Это proxy-target для разработки ML. Нулевая метка не означает подтверждённую исправность оборудования. Фактическая доступность датчиков и полнота доставки не установлены.

Снимки формируются в полночь UTC для каналов, у которых есть запись в предыдущем окне. Выбор канала в момент расчёта опирается на прошлое. Признаки используют интервал (t − 24 часа, t], метка использует (t, t + 24 часа]. Событие точно в t относится к признакам, событие точно в t + 24 часа относится к метке.

Начальные признаки ограничены числом записей, числом тревог и давностью последней записи и тревоги в прошлом окне. Значения кодов датчиков и сомнительный справочник состояний пока не превращаются в признаки отказа.

Строки с недостаточной историей канала, неполным будущим, пересечением известного разрыва журнала, текущим тревожным эпизодом или неизвестным началом будущего эпизода сохраняются с исключающей причиной и label=NULL. Их нельзя использовать как отрицательные обучающие примеры.

## Временное разделение

Выполненное разделение: train до 1 января 2025 года UTC, validation в 2025 году UTC, test с 1 января 2026 года UTC. Выбор сделан по календарным границам до оценки качества модели. Конкретные параметры сохранены в dataset-config.json.

Метки train и validation не должны достигать начала следующей части: конечная точка окна включена в метку. Исторические наблюдения из предыдущего периода допустимы в признаках следующего периода, если на момент расчёта они уже произошли. Преобразования признаков, пороги и калибровка впоследствии обучаются без test.

Справочник текущих объектов не используется для восстановления исторических связей. Признаки рассчитываются на уровне исходного канала. Времени поступления записей в данных нет, поэтому проверка будет основана на времени события и не воспроизведёт задержки доставки.

## Проверенные компоненты

prepare.py удаляет только полное совпадение исходных полей при включённом параметре и точное совпадение всех полей повторного заголовка. normalize.sql проверяет формат времени и признак тревоги, сохраняет строки ID и исходное значение. При ошибке частичный выход не публикуется, существующий файл не перезаписывается.

episodes.sql сохраняет правило последовательных временных разрывов. Равенство интервалу остаётся внутри группы. Суммирование по одинаковым временным отметкам учитывает все совпадающие строки одновременно, чтобы они не попадали в разные группы из-за неопределённого порядка равных времён.

```bash
PYTHONDONTWRITEBYTECODE=1 work/data-env/bin/python -m unittest discover \
  -s outputs/ml-dataset -p 'test_*.py'
```

Проверка подготовки данных включает сопоставление преобразования времени с Python ZoneInfo, сохранение разных событий с одинаковым ID, отключение дедупликации, позднюю ошибку записи, пустой вход и защиту существующего результата. Проверка SQL-эпизодов сравнивает весь результат, включая счётчики и обе границы, с iter_episodes из ml-stage2.

## Результат сборки

Режим: очистка, суточные признаки и метки, маски пропусков включены; обучение, инференс и трактовка тишины как исправности выключены. Интервал эпизода 900 секунд, порог выявления общей паузы журнала 3600 секунд. Результат находится в work/ml-prepared/training-examples.parquet, сводка в dataset-run.json, контрольные запросы в validation.json.

| Часть | Пригодные снимки канала | Положительные снимки |
|---|---:|---:|
| Train | 3 351 044 | 69 358 |
| Validation | 570 662 | 12 819 |
| Test | 318 303 | 8 444 |

Это числа снимков с известной рабочей меткой, не количество физических отказов и не число независимых эпизодов. Исключённые снимки сохранены отдельно по exclusion_reason. Несколько будущих эпизодов в одних сутках дают одну положительную метку.

Разрывы определяются по соседним записям всего журнала с точностью до временной отметки. Маска по полностью пустым датам оказалась недостаточной: после исправления снимки с частично отсутствующей историей также исключаются. Все шесть выявленных интервалов находятся в dataset-config.json. Паузы короче часа этим правилом не отсекаются. Наблюдаемость отдельных каналов остаётся неподтверждённой.

Для повторной сборки требуется новый путь результата: CLI не перезаписывает существующий файл. Команду запускать из корня рабочей папки.

```bash
PYTHONDONTWRITEBYTECODE=1 work/data-env/bin/python outputs/ml-dataset/build_dataset.py \
  work/ml-prepared work/ml-prepared/training-examples-rebuilt.parquet \
  outputs/ml-dataset/dataset-config.json
```

Снимок создаётся только для канала с записью за предшествующие сутки. Поэтому будущие эпизоды каналов без такой истории не попадают в обычную построчную оценку. Покрытие всех эпизодов следует измерять отдельно. Подробное ревью находится в REVIEW.md.
