# Ревью подготовки выборки

Выборка пригодна для эксперимента по прогнозу записанных тревожных эпизодов. Проверки не подтверждают физическую исправность, полноту доставки или работоспособность датчиков. Модель отказов по этим меткам заявлять нельзя.

## Исправленный дефект

Первоначальная маска использовала полностью пустые календарные даты. Проверка готовой выборки обнаружила окна с отсутствующей частью суток, которые ошибочно оставались пригодными. В частности, снимки на 10 апреля 2024 года использовали неполную историю предыдущих суток.

Исправление: log_gaps.sql группирует записи по UTC-часам и сравнивает крайние отметки соседних непустых групп. Для порога от часа этого достаточно: разрыв внутри одной часовой группы не может достичь часа. Маски начинаются на микросекунду позже последней записи и заканчиваются на следующей записи, не включая её. build_dataset.py принимает эти явные UTC-интервалы и проверяет порядок границ.

Режим исправленного запуска: полный проход, удаление точных повторов и заголовка, UTC и маски включены; обучение и инференс выключены. Порог общей паузы 3600 секунд, интервал эпизода 900 секунд. После исправления выполнены 20 временных CLI-проверок с разными внутрисуточными границами, все прошли; содержательные smoke-логи не сохранялись. Независимые проверки log_gaps.sql также сравнили 20 наборов времён с прямой сортировкой и поиском соседних записей.

На полном результате нет пригодных строк с пересечением выявленных пауз, границ train/validation/test или конца имеющегося будущего; нет повторных пар channel_id/as_of. Для 10 апреля исключены все 185 имеющихся снимков. Доказательства и параметры сохранены в validation.json. Старая выборка с календарной маской отложена в work для аудита, обучение использует исправленный файл.

## Корректность времени и меток

1. Признаки используют только (t − 24 часа, t]. Метки используют (t, t + 24 часа]. Тесты проверяют обе включённые границы и микросекунды вокруг них. Добавление будущих записей не меняет значения уже рассчитанных признаков.
2. SQL-эпизоды сопоставлены с независимым потоковым алгоритмом на 200 случайных наборах и отдельных граничных случаях. Счётчики сохраняют повторяющиеся временные отметки, gap равный порогу остаётся внутри эпизода.
3. Выборка сопоставлена с независимым Python-расчётом на 20 случайных наборах. Проверены несколько будущих эпизодов, активная тревога, неизвестное начало, пустой вход и переход между временными частями.
4. Все 21 тестовый метод модуля прошли одним запуском после изменения масок. Проверка подготовки включает 20 сопоставлений времени с ZoneInfo, сохранение разных событий с одинаковым ID и отсутствие опубликованного частичного файла при поздней ошибке.

Режим тестов: искусственные граничные данные, выбранные параметры явно переданы; обучение, инференс и сетевые вызовы выключены. Числа случайных примеров выше относятся к внутренним наборам тестов, а не к дополнительным независимым источникам данных.

## Архитектура, безопасность и производительность

SQL выполняет группировки до соединений, поэтому несколько будущих эпизодов не размножают снимки. Отсутствующая тревога остаётся NULL в признаке давности; её числовое заполнение относится к обучению модели. Каналы сохраняются строками, исторические связи с объектами не выдумываются.

CLI работает с лимитом DuckDB 1 GB, одним потоком и временным каталогом. Результат публикуется через создание ссылки без перезаписи существующего файла. Исходные архивы и подготовленные наблюдения не изменяются. Параметры SQL проверяются по типам; пути экранируются функцией literal. Гарантии для недоверенного публичного сервиса и удалённых файловых систем этим локальным CLI не проверялись.

Сборка рассчитана на подготовленные локальные таблицы. Она проверяет основные инварианты, но не является универсальным валидатором произвольной внешней схемы. В частности, название файла episodes-900.parquet и соседний отчёт с параметром должны соответствовать этому запуску. Контентные хеши prepared-файлов пока не связываются с отчётами автоматически.

## Ограничения и авторство

Порог общей паузы в час является консервативным правилом качества, не доказательством непрерывности. Короткие общие пропуски и пропуски отдельных каналов могут сохраниться. Времени доставки нет, часовой пояс Europe/Moscow принят по backend. Суточная сетка и история в сутки ограничивают покрытие; его нужно учитывать отдельно от recall на пригодных строках.

Эпизоды определяются эвристикой паузы, подтверждённого восстановления в данных нет. Возможна зависимость примеров одного канала и нескольких эпизодов в одном окне; обычный случайный split и независимые построчные доверительные интервалы здесь не подходят. Выбор gap и набора признаков должен выполняться без test.
